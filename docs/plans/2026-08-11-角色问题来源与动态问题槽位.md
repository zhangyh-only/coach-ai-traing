# 计划：分层决定角色问题并用动态槽位去重

## 目标

让正价 Elena 与奥莱 Bella 的问题由“场景边界 × 性格核心判断 × 产品适配主题”共同决定；不问容量，已问/已答的主题不重开，同时保留不同性格的问题顺序、证据门槛和语气差异。

## 范围

- 改：正价/奥莱角色扮演提示词，两场景的性格与产品随机卡，本场景测试 skill 的 `baseId=531` 实验口径，真模型回归与测试记录。
- 不改：Java 服务逻辑、数据库结构、STATE 三字段合同、评估链、产品 KB 事实。
- 假设/前置：`528` 是正价正式场景，`530` 是奥莱正式场景，`531` 只作正价实验组；用户已授权调整上述场景 prompt 与随机池。

## 步骤

1. 以 `528` 业务复现局作对照，记录“容量诱导、已答价格复问、已完成动作复做”表现。
2. 在正价候选 prompt 中建立最多两个动态问题槽位，以完整可见对话为主记录、STATE 为查漏；将容量改为仅现场目测/试装。
3. 调整 A/D 性格卡的核心判断、槽位顺序和证据门槛，并为正价产品卡补齐“体验焦点 / 适配主题”。
4. 将候选配置发布到 `531`，按同类 SA 诱导脚本与正常成交路径回归，对比 `528` 对照局。
5. 通过后同步正价 `528`；再将同一分层机制按 Bella 的渠道/价格/上身侧重适配到 `530`，不复制 Elena 问法。
6. 刷新测试报告与可视化记录，运行本地卫生检查，最后进行语义审查。

## 回滚方案

- 触发条件：动态槽位让普通对话大量提前暂缓，或 A/D 仍稳定出现同一提问指纹。
- 回滚动作：先将正式 `528/530` 提示词与随机池回填为 A/B 前的已记录版本；`531` 保留为独立实验场景继续调试。
- 影响面：回滚只影响角色扮演配置，不需要发布 Java 服务或迁移数据。
