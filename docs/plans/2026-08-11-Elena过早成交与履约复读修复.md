# 计划：修复 Elena 过早成交与成交后履约复读

> 状态：待用户审批。基于 2026-08-11 业务测试反馈；审批前不修改正式角色扮演提示词或线上配置。

## 目标

正价场景中的 Elena 不再因为一次试背和一句泛泛夸赞就直接成交；成交后严格沿履约流程单向推进，不重复索要新货、不重新评价陈列品，也不重复购买决定。

修复保留真人差异：不规定固定轮数或固定异议数量，只要求成交前至少出现并解决一个符合本局性格证据阈值的真实决策点。

## 范围

- 改：场景1正价角色扮演主提示词中的决策优先级、购买证据门槛、待履约状态推进和输出前检查。
- 改：新增一条针对本次反馈的正价场景聚焦回归话术，覆盖“泛泛夸赞后过早成交”和“成交后重复索要/重新评价”。
- 改：用 ADR 记录“成交前真实决策点、成交后履约单向推进”的长期行为合同。
- 不改：A-价值型、D-心动型性格卡；两张卡已经给出不同证据阈值，先修主提示词对性格卡的消费方式。
- 不改：产品随机池、奥莱 Bella 场景、实时评估链、整体评估链、知识库内容和业务后端。
- 不改：本轮不处理 `最新使用提示词.md` 与 `正价场景-最新使用提示词.md` 的命名/SSOT 指针不一致，避免把业务修复扩成目录治理。
- 假设/前置：当前修复基线为 `陪练场景搭建/场景1_质感自用Elena/正价场景-最新使用提示词.md` 与场景1最新随机池；线上真实版本仍需在本地接口恢复后回读确认。

## 方案取舍

1. 不采用固定 8–10 轮或固定 4 个异议：这会让顾客为了完成任务机械出题，重新引入旧版问题。
2. 不只加“禁止复读”句子：当前缺的是成交前后的状态转换，不是语言禁词。
3. 采用两道业务门：
   - 成交门：`购买` 只能在本局性格卡的证据阈值已满足后锁定。上身好看、颜色顺眼、导购泛泛说“很搭”只能形成购买信号；若导购尚未主动解决真实决策点，Elena 按本局性子自然提出一个临门关切或暂缓，不能直接成交。
   - 履约门：一旦 `表态=要买-CODE` 生效，只允许按“等待新货 → 验货 → 包装/付款 → 告别”单向前进。导购只口头答应时 Elena 简短承接并等待；结合上下文说“您看看这只怎么样”视为新货已到，完成一次验货，不重新评价颜色、比例、搭配或质感。

## 步骤

1. 修改 `陪练场景搭建/场景1_质感自用Elena/正价场景-最新使用提示词.md`：把性格卡证据阈值提升为购买决定的硬门槛，明确泛泛夸赞不构成成交证据，同时避免固定异议数量。
2. 在同一文件中把“待履约”细化为单向子状态，补齐口头承接、上下文式新货到场、验货和成交送别的转换规则，删除或合并与新状态机重复的散落说明。
3. 新增 `陪练场景搭建/场景1_质感自用Elena/记录/接口测试输出/sa_script_508_early_close_fulfillment_repeat.json`，复刻本次业务反馈的关键路径，并补一轮具体价值说明与包装完成话术，使整局可自然结束。
4. 新增 `docs/adr/0008-角色扮演成交门槛与履约单向推进.md`，记录为什么不用固定轮次/固定异议清单，以及主提示词与性格卡各自负责什么。
5. 运行文档卫生检查、结构断言和一次真实接口聚焦回归；若本地接口仍返回 502，保留离线检查结果并把真实模型稳定性明确列为待验证，不伪装通过。
6. 调用 `code-reviewer` 对正式提示词、回归话术和 ADR 做 fresh-context 语义审查，只修复本次范围内的阻断问题。
