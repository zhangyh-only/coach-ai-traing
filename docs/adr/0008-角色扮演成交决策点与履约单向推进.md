# 0008 - 角色扮演成交决策点与履约单向推进

## 背景与问题

2026-08-11 的正价 Elena 业务测试抽到 A-价值型性格卡和 CW631 产品卡。A 卡已经规定“先判断值不值”，并给出具体证据阈值；实际对话里，导购只完成试背并泛泛表示“特别搭”，Elena 却直接成交。成交后，Elena 又重复索要新货、重新评价陈列品的颜色和搭配，未按验货、包装和付款继续推进。

现行提示词已经有 `看包中 / 待履约 / 待离店` 三种决定后状态，也有性格卡和去重账本，但仍缺两类合同：

1. `看包中` 没有核验“本局关键决策点是否达到性格卡证据阈值”，模型可把一次体验和泛泛夸赞主观判断为信息已足够。
2. `待履约` 只规定允许拿新货、检查、包装和付款，没有区分请求已发出、正在等待、新货到场、已经验货等子状态，导致履约流程内复读和回退。

## 决策

我们决定：**不恢复固定五阶段；由每局性格卡的核心判断主题组织两个互补证据缺口，并优先通过主提示词消费完整对话和 `rolePlayState`，让体验、价值确认和决定后的离店或履约自然推进。场景调优不直接引入后端阶段硬编码。**

关键边界：

- 核心判断不是固定异议台词，也不是每局必须问完的通用清单。导购主动给出足够依据时，顾客可以直接消费证据；没有一次讲全时，顾客按性格卡先后确认两个互补缺口，例如使用频率与价格/服务承接。
- 两个互补缺口仍属于同一购买判断，不是恢复容量、材质、护理、搭配等逐项盘问。每个点只问一次，含糊时最多确认一次；已经回答就关闭，两项都到位后不再开启第三项。
- 顾客主动提出的购买缺口必须能在性格卡的关切、证据阈值或追问策略中找到直接依据；项目级生活背景只帮助自然表达，不能绕过随机卡新增容量、材质、护理等异议链。
- 上身好看、颜色顺眼、普通喜欢和泛泛夸赞只能形成购买信号，不能越过当前性格卡的证据阈值直接成交。
- 模型输出仍只使用 `关切 / 动作 / 表态` 三个 STATE 字段，不新增阶段字段；提示词沿完整对话的时间顺序判断当前是看包中、待履约还是待离店，`rolePlayState` 只作为去重索引和查漏证据。
- 购买决定和顾客异议只从 Elena 自己先前输出的正文及历史 STATE 判断；SA 的推荐、催单、口误和送客台词不能被反向当成 Elena 已购买、已暂缓或已经提问。
- 购买决定形成后，提示词从完整对话识别当前走到请求新货、等待、验货、包装/付款还是告别，并只向前推进；不把这些场景词写入后端服务。
- 首次成交轮提出“拿新的检查”只表示发起履约请求；导购没有明确表示新货已经到场时，同轮不得提前输出检查新包或 `验货-CODE`，不能把请求写成已完成动作。
- 当“已购买并请求新货”后导购只给一个肯定词时，使用最高优先级确定性拦截，只简短致谢等待；肯定词不等于新货到场，条件式履约安排也不等于验货事实。
- L1 主提示词负责关键决策门与履约状态；L2 A-价值型卡收敛为单一价格价值异议，明确证据阈值和取舍出口，避免长卡被模型读成容量、材质、护理等逐项清单。
- 本决策先落场景1 Elena；其它场景如需复用，必须结合自己的性格卡和成交逻辑单独验证，不能机械复制正价顾虑。
- 验收不要求随机模型 100% 逐字一致。当前业务标准是：典型成交路径在不复问、不重复动作的前提下，有足够的产品体验、两项互补确认和收尾承接；连同履约与告别通常约 10–14 个 SA↔顾客回合。明确拒绝或导购主动一次讲全时可以更短，不能为了轮数空转。
- 只有同类偏差在多次真实场景测试中仍高频出现，而且继续叠加提示词会明显伤害正常对话时，才另立技术方案评估通用、可配置的状态能力；不能用商品、场景或履约关键词硬编码补洞。

## 为什么

- **尊重随机性格**：A-价值型和 D-心动型已经有不同关切与证据阈值，主提示词应执行它们，而不是再写一套统一异议流程。
- **避免机械陪练**：历史五阶段标准问题清单曾把不同性格压成同一种提问指纹。一个关键决策点能保留训练难度，又不会为了轮次强行补题。
- **修复的是对话推进，不是禁词**：成交后复读来自模型没有稳定消费已发生事实，因此提示词同时给出决定锁和履约前进方向，而不是堆一串复读禁词。
- **保持部署边界**：仍使用现有 `{rolePlayState}`，不新增模型调用、数据库字段、第四个 STATE 输出字段或服务发布动作；本次调优全部留在场景配置层。

## 备选方案

- **恢复固定五阶段并规定异议数量**：不选。历史已验证会压平性格、制造固定问题清单，并诱发同类顾虑换皮复问。
- **新建独立异议执行器或异议库**：不选。当前性格卡已经提供关切、阈值和追问出口；再建一层会重复建模并把顾客演成考官。
- **只强化 A-价值型性格卡**：不作为单独方案。问题首先在主提示词没有把证据阈值作为购买门；真实接口复测又证明原 A 卡分支过多会被读成逐项清单，因此最终采用“L1 关键决策合同 + L2 A 卡减法收敛”的组合，而不是只在卡片继续加字。
- **只增加“禁止复读”规则**：不选。真实 `baseId=528` 多轮回归证明，模型即使已经输出 `表态=要买` 或 `表态=再想想`，下一轮仍会概率性重新解释长账本；只靠 prompt 无法稳定区分等待、新货到场、验货和包装。
- **在 Java 中派生固定阶段和履约关键词**：不选。它需要重新部署服务，还会把模型偶发写错的表态固化为阶段；场景变化后也容易继续增加关键词判断，不符合配置调优优先的维护边界。

## 影响与代价

- 正面：成交难度由本局性格决定；泛泛夸赞不再轻易成交；成交后的履约过程有明确下一步，同时无需发布 AI 服务。
- 代价：主提示词增加一组内部决策状态和履约子状态，必须控制篇幅并避免与既有决定、STATE、结束规则重复。
- 风险：模型仍存在偶发波动，不能承诺每次逐字一致；门槛写得过硬还可能让所有性格都强行提问或拖长对话。缓解方式是允许导购主动满足证据、只要求一个关键决策点，并用 A/D 两种启用性格做真实接口回归；同时把既有的产品身份展示和“旁白只写关键动作”作为回归保护项。

## 后续

- 用业务反馈路径回归当前正价场景 `baseId=528`，至少验证泛泛夸赞不能成交、具体价值依据可以成交、成交后等待和验货不复读。`497/507/508` 只作历史记录，不得作为当前验收证据。
- 随机池更新后要考虑 AI 运行侧最长约 2 分钟的配置缓存；只有新建 record 后从 `getRoleRandomData` 或 prompt trace 确认实际注入了目标卡片，才能将该局纳入验收。
- 真实模型出现两次以上相同偏差时再调整，不因单次随机波动扩写更多规则。
- 若 Bella 也出现同类成交门问题，基于奥莱的渠道、价格和买错风险单独设计，不能直接复制 Elena 的价值关切。
- 若连续回归证明 prompt 已接近上限，再另行评审通用配置化状态机制的收益与发布成本；该决策不属于本次 528 调优。
